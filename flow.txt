## 3. Complete code flow (A–Z)

### 3.1 Application startup flow

```
1. server.ts
   └─> Load environment variables
   └─> Connect to database
   └─> Initialize database tables
   └─> Start Express server
   └─> Listen on PORT

2. app.ts
   └─> Initialize Express app
   └─> Apply security middleware (Helmet)
   └─> Apply rate limiting
   └─> Setup session management
   └─> Setup body parsing
   └─> Setup view engine (EJS)
   └─> Mount routes
   └─> Setup error handlers
   └─> Setup 404 handler
```

### 3.2 Request flow

```
HTTP Request
    ↓
1. Helmet (Security Headers)
    ↓
2. Rate Limiter (express-rate-limit)
    ├─> Check IP-based limits
    └─> Reject if exceeded
    ↓
3. Cookie Parser
    ↓
4. Body Parser (JSON/URL-encoded)
    ↓
5. Session Middleware
    ↓
6. CSRF Token Generation
    ↓
7. Route Matching
    ├─> Page Routes (EJS rendering)
    └─> API Routes (JSON responses)
    ↓
8. Route-Specific Middleware
    ├─> Authentication (JWT/Session)
    ├─> Validation (Zod)
    └─> Authorization checks
    ↓
9. Controller/Handler
    ├─> Validate input
    ├─> Call Service Layer
    ├─> Database queries
    └─> Format response
    ↓
10. Response
    ├─> Render EJS (Page routes)
    └─> Send JSON (API routes)
```

### 3.3 User authentication flow

```
1. User visits /auth
   └─> Render auth.ejs
    ↓
2. User enters email → POST /api/auth/login/start
   └─> Validate email (Zod)
   └─> Check if user exists
   └─> Generate 6-digit OTP
   └─> Hash OTP (bcrypt)
   └─> Store in OTP table
   └─> Send email via Nodemailer
   └─> Return success
    ↓
3. User enters OTP → POST /api/auth/login/verify
   └─> Validate OTP (Zod)
   └─> Find OTP in database
   └─> Check expiry (10 minutes)
   └─> Verify hash (bcrypt)
   └─> Mark OTP as used
   └─> Create/Get user
   └─> Generate JWT token
   └─> Set JWT in cookie
   └─> Create session
   └─> Redirect to /dashboard
```

### 3.4 Twin creation flow

```
1. User visits /twin/create
   └─> Render twin_create.ejs
    ↓
2. User uploads 3-5 text samples → POST /api/twin/create
   └─> Validate samples (Zod: 100-3000 chars)
   └─> Safety check (blacklist, toxicity)
   └─> Extract style using OpenAI
       ├─> Build prompt with samples
       ├─> Call OpenAI GPT-4o-mini
       ├─> Extract style vector (tone, emoji, hinglish, etc.)
       └─> Generate sample reply
   └─> Store in database
       ├─> Create Twin record
       ├─> Store styleVector (JSON)
       ├─> Store sampleReply
       └─> Link to User
   └─> Log event (twin_created)
   └─> Return twin data
    ↓
3. User sees preview
   └─> Can approve/reject
   └─> Option to make public
```

### 3.5 Chat flow (private)

```
1. User starts chat → POST /api/chat/start
   └─> Validate twinId
   └─> Check user owns twin
   └─> Create Chat record
   └─> Return chatId
    ↓
2. User types message
   └─> Frontend validates length
    ↓
3. User requests draft → POST /api/chat/:id/draft
   └─> Rate limit check (1 per 30s)
   └─> Get chat history
   └─> Get twin styleVector
   └─> Build OpenAI prompt
       ├─> Include style vector
       ├─> Include conversation context
       └─> System prompt for style
   └─> Call OpenAI API
   └─> Generate draft response
   └─> Store draft in Message (approved=false)
   └─> Return draft to user
    ↓
4. User approves → POST /api/chat/:id/send
   └─> Validate messageId
   └─> Mark message as approved=true
   └─> Update chat timestamp
   └─> Log event (message_approved)
   └─> Return success
```

### 3.6 Public chat flow

```
1. User visits /public-twin/chat/:twinId
   └─> Check twin is public
   └─> Get twin details
   └─> Check for existing chat (by userId or visitorId)
   └─> Render public-chat.ejs
    ↓
2. Start/Resume chat → POST /api/public-chat/start
   └─> Get/create PublicChat record
   └─> Return chatId
    ↓
3. User sends message → POST /api/public-chat/:chatId/message
   └─> Validate content
   └─> Create PublicMessage (sender=human)
   └─> Update message count
    ↓
4. Generate AI response → POST /api/public-chat/:chatId/draft
   └─> Get chat history
   └─> Get twin style
   └─> Generate AI draft
   └─> Create PublicMessage (sender=twin)
   └─> Return message
```

### 3.7 Discover & social flow

```
1. User visits /discover
   └─> Fetch trending twins → GET /api/discover/trending
       ├─> Query by likeCount, chatCount
       └─> Return twin list
    ↓
2. User likes twin → POST /api/social/twin/:id/like
   └─> Check if already liked
   └─> Create TwinLike record
   └─> Increment likeCount
   └─> Return success
    ↓
3. User follows twin → POST /api/social/twin/:id/follow
   └─> Check if already following
   └─> Create TwinFollow record
   └─> Increment followCount
   └─> Return success
```

### 3.8 Memory & learning flow

```
1. Background Learning Scheduler (cron)
   └─> Runs every hour (production)
   └─> Gets all active twins
   └─> For each twin:
       ├─> Analyze recent chats
       ├─> Extract style patterns
       ├─> Update styleVector
       └─> Update systemPrompt
    ↓
2. Memory Management
   └─> User adds memory → POST /api/memory/:twinId/memory/ingest
       ├─> Categorize (facts/voice)
       ├─> Generate embedding (optional)
       └─> Store in mem_chunks
   └─> Retrieve memories → GET /api/memory/:twinId/memory/retrieve
       └─> Filter by bucket
       └─> Return relevant memories
```

# Chat delete functionality — analysis & strategy

## Current codebase analysis

### 1. Database structure

#### Private Chat (`Chat` table):
- Table: `Chat`
- Messages: `Message` (FK: `chatId` → `Chat.id` ON DELETE CASCADE)
- Session Memory: `MemorySession` (FK: `chatId` → `Chat.id` ON DELETE CASCADE)
- Foreign keys: `userId`, `twinId` (both CASCADE)

#### Public Chat (`PublicChat` table):
- Table: `PublicChat`
- Messages: `PublicMessage` (FK: `chatId` → `PublicChat.id` ON DELETE CASCADE)
- Foreign keys: `twinId` (CASCADE), `userId`/`visitorId` (nullable)

Important: CASCADE constraints already exist, so deleting a chat will delete related messages automatically.

---

### 2. Current API endpoints

#### Private Chat (`/api/chat`):
- `POST /api/chat/start` - Start chat
- `GET /api/chat` - Get user's chats
- `GET /api/chat/:id` - Get specific chat
- `POST /api/chat/:id/draft` - Generate draft
- `POST /api/chat/:id/send` - Send message
- `GET /api/chat/history` - Get chat history
- `GET /api/chat/:id/messages` - Get messages
- `POST /api/chat/:id/message` - Handle user message

Missing: `DELETE /api/chat/:id`

#### Public Chat (`/api/public-chat`):
- `POST /api/public-chat/start` - Start public chat
- `GET /api/public-chat/:chatId/history` - Get chat history
- `POST /api/public-chat/:chatId/message` - Send message
- `GET /api/public-chat/twin/:twinId` - Get chat by twin
- `GET /api/public-chat/twin/:twinId/chats` - Get all chats for twin
- `POST /api/public-chat/create` - Create new chat
- `GET /api/public-chat/user/my-chats` - Get user's public chats

Missing: `DELETE /api/public-chat/:chatId`

## Detailed implementation plan

### Step 1: Backend - Private Chat Delete

1. Create `deleteChat` function in `chatController.ts`
   - Verify `chat.userId === req.user.id`
   - Delete from `Chat` table
   - CASCADE will handle messages
   - Return success response

2. Add route in `chatRoutes.ts`
   - `DELETE /:id` with auth + CSRF

3. Error handling
   - Chat not found
   - Unauthorized (chat doesn't belong to user)
   - Database errors

### Step 2: Backend - Public Chat Delete

1. Create `deletePublicChat` function in `publicChatController.ts`
   - Check ownership: `userId` (if logged in) or `visitorId` match
   - Delete from `PublicChat` table
   - CASCADE will handle messages
   - Return success response

2. Add route in `publicChatRoutes.ts`
   - `DELETE /:chatId` with optional JWT

3. Error handling
   - Chat not found
   - Unauthorized (for authenticated users)
   - Anonymous user validation (visitorId match)

### Step 3: Frontend - UI updates

1. Update `displayChatHistory()` in `chat-enhanced.ejs`
   - Add delete button HTML in each chat item
   - Position: Absolute top-right
   - Show on hover
   - Add click event listener

2. Update `displayPublicChatHistory()` in `public-chat.ejs`
   - Same changes as above

### Step 4: Frontend - JavaScript functions

1. Add `deleteChat()` function
   - Confirmation dialog
   - API call to `DELETE /api/chat/:id`
   - UI update on success
   - Handle current chat deletion

2. Add `deletePublicChat()` function
   - Same logic for public chats

### Step 5: Edge cases

1. Current chat deletion
   - If deleted chat is currently open, switch to another chat
   - If no other chats, create new chat or show empty state

2. Last chat deletion
   - Show empty state message
   - Option to create new chat

3. Error handling
   - Network errors
   - Server errors
   - User feedback (toast/alert)

## Security considerations

1. Authentication
   - Private chat: Must be authenticated
   - Public chat: Optional auth, but verify ownership

2. Authorization
   - Users can only delete their own chats
   - Verify `userId` or `visitorId` match

3. CSRF protection
   - Include CSRF token in DELETE requests
   - Validate on backend

4. Rate limiting
   - Consider rate limiting delete operations
   - Prevent abuse

---

## UI/UX considerations

1. Delete button visibility
   - Show on chat item hover
   - Small, unobtrusive icon
   - Red color on hover for clarity

2. Confirmation dialog
   - "Are you sure you want to delete this chat?"
   - "This action cannot be undone"

3. Feedback

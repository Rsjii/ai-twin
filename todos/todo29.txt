### 1. Why “Today / 7 Days / Monthly” buttons + cards are breaking

**Root cause (from logs):**

- Error: `column reference "createdAt" is ambiguous` in `getTimeBasedAnalytics` (`adminAnalyticsController.ts:738`).
- This happens in queries where **multiple tables are joined** and we use a generic `WHERE ${timeFilter}` built as:

```ts
// Example
timeFilter = '"createdAt" >= NOW() - INTERVAL \'7 days\'';
...
SELECT ... FROM "User" u LEFT JOIN "Event" e ON ...
WHERE ${timeFilter}   // <- ambiguous: both u and e have "createdAt"
```

**Consequence:**

- `GET /api/admin/analytics/time/today|week|month` → 500 error  
  ⇒ frontend `loadTimeBasedAnalytics(...)` fails ⇒ buttons feel “dead”.
- Same API is also used by **detailed modal** for time-based views → “All Time cards” (actually the time-based detail) also error.

### 2. Quick fix plan for time-based analytics (Point 1 & 2)

**File:** `backend/src/modules/analytics/adminAnalyticsController.ts`  
**Function:** `getTimeBasedAnalytics`

#### 2.1 Make time filters alias-specific

Instead of a single `timeFilter`, define per-table filters:

```ts
let userTimeFilter = '';
let twinTimeFilter = '';
let eventTimeFilter = '';

switch (period) {
  case 'today':
    userTimeFilter  = 'u."createdAt" >= CURRENT_DATE AND u."createdAt" < CURRENT_DATE + INTERVAL \'1 day\'';
    twinTimeFilter  = 't."createdAt" >= CURRENT_DATE AND t."createdAt" < CURRENT_DATE + INTERVAL \'1 day\'';
    eventTimeFilter = 'e."createdAt" >= CURRENT_DATE AND e."createdAt" < CURRENT_DATE + INTERVAL \'1 day\'';
    break;
  case 'week':
    userTimeFilter  = 'u."createdAt" >= NOW() - INTERVAL \'7 days\'';
    twinTimeFilter  = 't."createdAt" >= NOW() - INTERVAL \'7 days\'';
    eventTimeFilter = 'e."createdAt" >= NOW() - INTERVAL \'7 days\'';
    break;
  case 'month':
    userTimeFilter  = 'u."createdAt" >= NOW() - INTERVAL \'30 days\'';
    twinTimeFilter  = 't."createdAt" >= NOW() - INTERVAL \'30 days\'';
    eventTimeFilter = 'e."createdAt" >= NOW() - INTERVAL \'30 days\'';
    break;
}
```

For **single-table** queries you can keep using a simple version:

```ts
const simpleTimeFilter = timeFilterFor('"createdAt"', period); // or inline like now
```

#### 2.2 Apply correct filter per query

Current block:

```ts
db.query(`SELECT COUNT(*) as count FROM "User" WHERE ${timeFilter}`),
...
db.query(`SELECT EXTRACT(HOUR FROM "createdAt") ... FROM "Event" WHERE ${timeFilter}`),
...
db.query(`
  SELECT u... FROM "User" u
  LEFT JOIN "Event" e ON ...
  WHERE ${timeFilter}
  ...
`),
db.query(`
  SELECT t..., u.handle ...
  FROM "Twin" t JOIN "User" u ...
  WHERE ${timeFilter}
  ...
`)
```

Change to something like:

```ts
// Counts (single table)
db.query(`SELECT COUNT(*) as count FROM "User" WHERE ${userSimpleFilter}`),
db.query(`SELECT COUNT(*) as count FROM "Twin" WHERE ${twinSimpleFilter}`),
db.query(`SELECT COUNT(*) as count FROM "Chat" WHERE ${chatSimpleFilter}`),
db.query(`SELECT COUNT(*) as count FROM "Message" WHERE ${messageSimpleFilter}`),
db.query(`SELECT COUNT(*) as count FROM "Event" WHERE ${eventSimpleFilter}`),

// Event hourly/daily
db.query(`SELECT EXTRACT(HOUR FROM e."createdAt") ... FROM "Event" e WHERE ${eventTimeFilter} GROUP BY ...`),
db.query(`SELECT DATE(e."createdAt") ... FROM "Event" e WHERE ${eventTimeFilter} GROUP BY ...`),

// Top users IN THIS PERIOD: filter on Event timestamps (activity in window)
db.query(`
  SELECT u..., COUNT(e.id) as eventCount
  FROM "User" u
  LEFT JOIN "Event" e ON u.id = e."userId"
  WHERE e."createdAt" >= ...   -- use eventTimeFilter
  GROUP BY u.id ...
  ORDER BY eventCount DESC
  LIMIT ...
`),

// Top twins IN THIS PERIOD: filter on twin createdAt or event twin-related
db.query(`
  SELECT t..., u.handle as userHandle
  FROM "Twin" t
  JOIN "User" u ON t."userId" = u.id
  WHERE t."createdAt" >= ...   -- use twinTimeFilter
  ORDER BY t."likeCount" DESC, t."chatCount" DESC
  LIMIT ...
`),
```

**Result after this change:**

- `/api/admin/analytics/time/today|week|month` will return:
  - `summary` (users/twins/chats/messages/events for that period)
  - `breakdown` (hourly/daily from `Event`)
  - `topContent.users` / `topContent.twins` based on **activity in that window**
- Frontend time tabs + detailed modal will stop erroring and show real data.

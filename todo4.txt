## 1) Critical / high-risk fixes (do these first)

### 1.1 Token & prompt explosion protection

**Why:** Long memory + style + session + chatContext can blow past model token limits (cost + failure).
**How:** enforce prompt assembly pipeline that: (a) measures token budget, (b) ranks candidate memories/style anchors by importance, (c) truncates/omits low-priority items, (d) fallbacks to compressed summaries. Add strict `max_prompt_tokens` per twin (already have `tokenLimit` but enforce at build time).
**Effort:** S

### 1.2 Rate limiting & abuse protection per twin & per IP

**Why:** Public chats + anonymous visitors can be spam/DoS.
**How:** apply rate limits on `POST /api/public-chat/:id/message` per visitorId/IP and per twinId; throttle anonymous usage heavier. Use request counters + exponential backoff. Log violations to `Event`.
**Effort:** S

### 1.3 Moderation automation + human-in-loop for public chats

**Why:** Public twin replies can be unsafe. Approve-only backlog will block UX if manual heavy.
**How:** run automatic moderation (OpenAI moderation or simple classifier) on outgoing AI messages & incoming user messages. Auto-allow safe; flag uncertain for review. Provide moderator UI to approve/ban. Store moderation decisions in `ContentReport`.
**Effort:** M

### 1.4 Persistent idempotency for critical endpoints

**Why:** Duplicate messages / retries can create duplicate saves & skew analytics (ai_runs, message counts).
**How:** require client-generated `requestId` for `POST /api/chat/:id/message`, check unique constraint in DB.
**Effort:** S

### 1.5 Sensitive data safety & GDPR basics

**Why:** Long-term memory stores user facts; you must allow users to view/delete memories.
**How:** add `GET/DELETE /api/twin/:id/long-term-memory/:key` clearly, and audit logs for deletion. Add retention policy & export endpoint. Update Privacy page.
**Effort:** M

## 3) ML / memory / prompt improvements (keep lightweight)

### 3.1 Retrieval ranking & pruning policy for long-term memories

**Why:** Many memories → noise.
**How:** store `confidence` and `lastAccessed` in `MemoryLongTerm`. When retrieving, sort by `relevanceScore * confidence * recencyBoost`. Periodically prune low-value items (`confidence < 0.2` & not accessed in 180d).
**Effort:** M

### 3.2 Style anchors: do few-shot only + small set in prompt

**Why:** Too many anchors increases tokens.
**How:** limit to top-3 anchors per request; prefer `phrase` type + specific examples. Simple similarity search (cosine) on short embeddings to pick top items. Consider storing small `anchor_vector` (use text-embedding-3-small).
**Effort:** M (embedding infra)

### 3.3 Fallback model & cost control

**Why:** GPT calls expensive / failing.
**How:** configure `primaryModel` + `fallbackModel` (cheaper) and set behavioral differences (e.g., shorter replies on fallback). Track `ai_runs.regen` and model used.
**Effort:** S
